# المرحلة التاسعة [P09]: الاختبار، جودة الكود (Testing, Code Quality)

أنا مهندس برمجيات أهدف إلى بناء فهم هندسي متين يساعدني على تحليل المشكلات، وفهم سلوك الأنظمة، واتخاذ قرارات تقنية مبررة، وتطوير برمجيات موثوقة قابلة للاختبار والصيانة والتوسع. أفضّل استخدام **Python** و**PostgreSQL**، وأعتمد **FastAPI** في المسار التطبيقي لتطوير الخدمات الخلفية؛ لذلك تربط هذه الخطة بين الأسس النظرية والتطبيق العملي باستخدام هذه التقنيات.

**هدف المرحلة:** بناء اختبارات ذات قيمة، اكتشاف الأخطاء بطريقة منهجية، تعديل الكود بثقة أكبر.

## 1. أساسيات الاختبار (Testing Fundamentals)

- حالات الاختبار، السيناريوهات - Test Cases, Test Scenarios
- الحالات الطبيعية، الاستثنائية - Positive, Negative Testing
- تحليل القيم الحدية، تقسيم فضاءات المدخلات - Boundary Value Analysis, Equivalence Partitioning
- اختبار الانحدار، الاختبار الاستكشافي - Regression Testing, Exploratory Testing

## 2. مستويات الاختبار (Testing Levels)

- اختبار الوحدات، التكامل، المكونات - Unit, Integration, Component Testing
- اختبار العقود - Contract Testing
- اختبار النظام من البداية إلى النهاية - End-to-End Testing
- هرم الاختبارات - Test Pyramid
- اختبار الأداء، الأمن (نظرة) - Performance, Security Testing (Overview)

## 3. تصميم الاختبارات (Test Design)

- قابلية الاختبار - Testability
- الكائنات البديلة: المحاكاة، البدائل الوهمية، التطبيقات البديلة - Test Doubles: Mocks, Stubs, Fakes
- تجهيز بيانات الاختبار - Test Fixtures
- الاختبارات الحتمية، غير المستقرة - Deterministic, Flaky Tests
- اختبار مسارات الفشل - Failure-Path Testing
- اختبار الكود غير المتزامن - Asynchronous Testing
- قاعدة بيانات حقيقية مقابل بديلة - Real vs Fake Databases

## 4. مناهج الاختبار (Testing Approaches)

- التطوير المدفوع بالاختبارات - Test-Driven Development
- الاختبار القائم على الخصائص (مدخل) - Property-Based Testing (Introduction)
- *اختياري:* التطوير المدفوع بالسلوك، اختبار الطفرات - Behavior-Driven Development, Mutation Testing

## 5. جودة الكود (Code Quality)

- التحليل الساكن، الفحص، التنسيق - Static Analysis, Linting, Formatting
- تغطية الاختبارات، حدودها - Test Coverage, Its Limits
- تعقيد الكود - Code Complexity
- الفحوصات الآلية قبل الدمج - Automated Pre-Merge Checks

## 6. تصحيح الأخطاء (Debugging)

- نقاط التوقف، تتبع التنفيذ - Breakpoints, Execution Tracing
- سجلات الأخطاء، تتبع المكدس - Error Logs, Stack Traces
- إعادة إنتاج الأخطاء - Bug Reproduction
- تحليل السبب الجذري - Root Cause Analysis
- تحليل الذاكرة، الأداء - Memory, Performance Profiling

## التدريبات العملية (Practical Exercises)

1. اكتب 25 اختبار وحدة لوحدة منطق (حاسبة خصومات) تشمل حالات حدية، سلبية، مع اختبارات مُعلمَة بمدخلات متعددة (القسمان 1، 2).
2. طبق التطوير المدفوع بالاختبارات على دالة جديدة: ثلاث دورات (فشل، نجاح، تحسين)، كل دورة بالتزام مستقل في جيت (القسم 4).
3. اكتب اختبار تكامل مع بوستجريس حقيقي في حاوية، بحيث يبدأ كل اختبار بمعاملة ويتراجع عنها في النهاية (القسم 3).
4. استبدل خدمة خارجية بتطبيق بديل، ثم بمحاكاة، وقارن هشاشة الاختبارين عند تغيير التنفيذ الداخلي (القسم 3).
5. أنتج اختبارًا غير مستقر عمدًا (بالزمن، العشوائية، الترتيب)، ثم أصلحه (القسم 3).
6. قس التغطية، ثم أدخل خطأ في سطر مغطى، لاحظ هل تكتشفه الاختبارات؛ اكتب ما تعلمته عن حدود التغطية (القسم 5).
7. أعد إنتاج خطأ في برنامج لا تعرفه: اكتب خطوات الإعادة، حدد السبب الجذري، اكتب اختبار انحدار يمنع عودته (القسم 6).

**المخرج:** مجموعة اختبارات منظمة لمشروع سابق، إعداد فحوصات قبل الدمج، ملف يوثق منهجك في تتبع الأخطاء.

**معيار الانتقال:**

- تكتب اختبارًا يفشل لسبب واحد واضح.
- تعرف متى تستخدم المحاكاة، متى تفضل قاعدة بيانات حقيقية.
- تحول خطأً مبلغًا عنه إلى اختبار يفشل، ثم تصلحه.
- تفسر لماذا لا تضمن التغطية العالية جودة الاختبارات.
